# High-Performance Big Data Analytics Using R

## Overview

This project implements **Laboratory Assignment 8** using the NYC Taxi &
Limousine Commission (TLC) Yellow Taxi Trip Records. It explores
transportation patterns and compares different R programming approaches
for processing large datasets.

The implementation is provided in a Google Colab notebook:
`ProgramR_PBL8.ipynb`.

## Objectives

-   Acquire, inspect, clean, and transform NYC Yellow Taxi trip records.
-   Join trip data with the NYC Taxi Zone Lookup Table.
-   Analyze taxi demand, fare amounts, revenue, trip distances, routes,
    and payment methods.
-   Compare vectorized R operations, `apply()`, `lapply()`,
    `purrr::map()`, and `data.table`.
-   Compare sequential and parallel processing using `foreach` and
    `doParallel`.
-   Benchmark execution time and calculate parallel speedup.
-   Visualize key findings using `ggplot2`.
-   Discuss performance, memory use, scalability, and readability.

## Dataset

-   **Source:** [NYC TLC Trip Record
    Data](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page)
-   **Trip data:** Yellow Taxi records for January 2024
-   **Format:** Parquet
-   **Zone lookup:** CSV

The notebook downloads these files from the NYC TLC data distribution
service:

-   `yellow_tripdata_2024-01.parquet`
-   `taxi_zone_lookup.csv`

The notebook initially uses January 2024 to keep the workflow manageable
while still processing a large dataset. A multi-month extension can be
used when month-to-month comparisons are required.

## Technologies and R Packages

-   **R** --- programming language
-   **data.table** --- fast filtering, grouping, joins, and aggregation
-   **arrow** --- reading Parquet files
-   **lubridate** --- extracting date and time features
-   **purrr** --- functional programming with `map()`
-   **foreach** and **doParallel** --- parallel processing
-   **microbenchmark** --- comparing execution times
-   **ggplot2** --- data visualization

## Implementation Workflow

1.  **Environment setup:** Install and load the required R packages.
2.  **Data acquisition:** Download the taxi trip dataset and zone lookup
    table.
3.  **Inspection and preparation:** Inspect dimensions, data types, and
    summary statistics; remove duplicates and records that violate the
    notebook's cleaning rules; derive pickup hour, day, weekday, and
    trip duration.
4.  **Zone integration:** Join pickup and drop-off location IDs to zone
    names and boroughs.
5.  **Transportation analytics:** Calculate demand by hour and weekday,
    fare and revenue summaries, trip-distance relationships, popular
    routes, high-revenue routes, and payment-method distributions.
6.  **Programming comparison:** Compare vectorized calculations,
    `apply()`, `lapply()`, `purrr::map()`, and `data.table`.
7.  **Parallel computing:** Partition the records, execute the same
    aggregation sequentially and in parallel, and calculate speedup.
8.  **Benchmarking:** Measure execution times for alternative
    implementations.
9.  **Visualization:** Create charts with `ggplot2`.
10. **Reporting:** Print a summary of experimental results and save
    selected result tables as CSV files.

## Performance Evaluation

The experiment evaluates the approaches using:

-   Median and elapsed execution time
-   Approximate in-memory object size
-   Scalability for large datasets
-   Code readability and complexity
-   Parallelization overhead

Parallel processing is not guaranteed to be faster. Worker startup, task
scheduling, and data transfer can outweigh the benefits for small or
inexpensive tasks.

## Limitations

-   The main workflow uses January 2024 records, so it cannot establish
    meaningful month-to-month trends from multiple months on its own.
-   Data cleaning rules affect the number and characteristics of records
    retained.
-   Runtime and benchmark results vary with available CPU cores, memory,
    and Colab session conditions.
-   The object-size measurement is an approximation and does not
    represent total peak memory consumption.
-   The dataset represents recorded taxi trips and should be interpreted
    within the coverage and limitations of the source data.

## Conclusion

This project demonstrates an end-to-end R analytics workflow for
large-scale taxi trip data. It combines data preparation, `data.table`
operations, functional and vectorized programming, parallel computing,
benchmarking, and visualization. The most appropriate approach should be
selected from measured results, considering execution time, memory
requirements, readability, and scalability.
